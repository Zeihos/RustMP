# RUSTMP — 0.2.0-alpha.11

> **Техническая alpha-версия, НЕ готовый игровой сервер.** Существующие клиенты GTA San Andreas пока не могут войти. Все объекты и игроки из `rustmp-core` используются лишь как внутренние структуры данных и тестовые фикстуры.

RUSTMP — самостоятельная разработка совместимой с SA-MP/open.mp серверной платформы на Rust, **не** игровой RP-мод и **не** обёртка над C++.

## Что реализовано

- Cargo workspace из четырёх Rust-крейтов: `rustmp-server`, `rustmp-core`, `rustmp-protocol`, `rustmp-transport`.
- Обработка SA-MP UDP Query `i`, `r`, `c`, `d`, `p` в том же UDP-сокете, что и RakNet.
- **Сетевой этап 0.2.0-alpha.1:** первый офлайн-обмен старого RakNet из SA-MP: `ID_OPEN_CONNECTION_REQUEST` (3 байта) → `ID_OPEN_CONNECTION_REPLY` (2 байта).
- Обработка старого unconnected RakNet ping (5 байт, timestamp) и pong (5 байт). Дополнительные серверные данные для pong пока не формируются.
- Отдельный модуль `rustmp-transport` с лимитом запросов на IP, ограничением незавершённых слотов, ограничением памяти счётчика IP, таймаутом незавершённых подключений.
- Пул игроков и транспорта, серверный мир, начальный BitStream, кодировки CP1251/CP1252.
- **Alpha.3:** внутренний модуль надёжной доставки: ограниченная очередь ACK, повторная отправка с таймаутом и числом попыток, подавление дублей с 16-битным переполнением, 32 канала упорядочивания. Всё это пока **не подключено к игровому сетевому протоколу**.
- Тесты кодирования пакетов, таймаутов, повтора/флуда и совместного использования UDP-порта.
- GitHub Actions CI (Linux/Windows) и простой клиент проверки offline handshake.

- **Alpha.4:** отдельный битовый кодек префикса ACK/RangeList старого RakNet (`rustmp-protocol::ack`), тестовые векторы, проверка некорректных/усечённых пакетов; добавлена передача декодированных ACK в очередь resend. Этот код пока не подключён к живым игровым сессиям.

- **Alpha.5:** безопасный кодек несегментированных RakNet datagram: ACK-префикс + 4-битные типы надёжности SA-MP (6–10), 16-битные номера, 5-битные каналы, 16-битные индексы порядка, сжатая длина payload, выравнивание по байту. Добавлены фиксированный wire-вектор и тесты повреждённых/усечённых пакетов. **Кодек пока не обрабатывает реальные UDP-сессии**.

- **Alpha.6:** битовый формат `SplitInfo { id: u16, index: compressed u32, count: compressed u32 }` в `rustmp-protocol::legacy_frame`, кодирование/чтение фрагментов и их отдельная сборка через `rustmp-transport::fragments::SplitAssembler`. Защита: лимит количества фрагментов, размера сообщений, количества параллельных групп, общей памяти, таймауты, отклонение противоречащих частей. Обработка доступна **только как библиотека**, не используется при приёме UDP-пакетов от игроков.

- **Alpha.7:** изолированный менеджер подтверждённых сессий `rustmp-transport::session::VerifiedSessions`: строгая привязка по `SocketAddr`, объединение ACK, дедупликации, упорядочивания и фрагментации, лимит 128 сессий, idle timeout 60 секунд и ограниченные очереди. Сессии **не создаются из offline handshake**, и этот менеджер **не подключён к игровому UDP-приёмнику**. Это самостоятельная тестируемая заготовка для будущего подтверждённого соединения.

- **Alpha.8:** разделены два профиля служебных RakNet-пакетов: SA-MP 0.3.7 (числовые значения из `Alf21/samp`) и `RAKNET_LEGACY` из `openmultiplayer/RakNet`. Один UDP-порт распознаёт оба формата трёхбайтового offline-open и пятибайтового ping. После предварительного слота сервер теперь **только наблюдает** первый корректный надёжный запрос `ID_CONNECTION_REQUEST` от того же адреса и считает такие события. Источник, пароль, auth challenge, игровая авторизация и настоящие сетевые сессии ещё **не подтверждаются**.

- **Alpha.9:** добавлен изолированный `rustmp-transport::handshake::HandshakeCoordinator` для следующих шагов RakNet: проверка пароля из `ID_CONNECTION_REQUEST`, формирование `ID_CONNECTION_REQUEST_ACCEPTED`, open.mp `ID_AUTH_KEY` challenge/response и проверка `ID_NEW_INCOMING_CONNECTION`. Два профиля имеют отдельные ID сообщений; внутри попытки зафиксированы исходный адрес, время начала и ожидаемая стадия. Таблицу challenge/response **не подменяем фиктивной**: для open.mp приложение обязано передать настоящую совместимую пару извне, и без неё handshake не начинается. **В живой UDP-приёмник этот модуль ещё не включён**.

- **Alpha.10:** новый библиотечный модуль `rustmp-transport::preauth::PreAuthExchange` объединяет handshake alpha.9 с ACK, дедупликацией, таймаутами, и повторной отправкой надёжных RakNet-датаграмм. Для SA-MP формируется ответ о принятии соединения, для open.mp — auth challenge и последующий ответ после сверки пары. В тестах проверяются обе ветки, потеря ACK, повторная отправка с исходным sequence, отказ при ошибочном auth. **Модуль пока не подключён к входящему UDP-сокету**.

- **Alpha.11:** `--experimental-preauth` включает ограниченный **только IPv4 localhost** реальный UDP-маршрут предварительного SA-MP 0.3.7 handshake. Сервер отвечает reliable-датаграммой c ACK первого клиентского пакета, обрабатывает повторные ACK/передачи и финальное подтверждение, отправляет resend-пакеты на правильные адреса. При завершении транскрипта **сессия удаляется**, никаких реальных игроков в `World` не добавляется. Режим по умолчанию выключен; включение на `0.0.0.0`, публичном IP или IPv6 отклоняется. **Open.mp live auth/cookie запрещён до реализации реальной защиты.**

**Не реализованы:** полноценный handshake/проверка auth challenge, подтверждённые игровые сессии, сетевые ACK и resend для живых клиентов, RPC, создание игроков, синхронизация, Pawn AMX и плагины open.mp. `pending`-слот **не** означает подключённого игрока.

## Как проверить на Windows

1. Установить Rust + Cargo: https://rustup.rs/.
2. Клонировать репозиторий или скачать исходники с GitHub.
3. Запустить `test-windows.bat` (проверка Cargo workspace) или вручную:

```powershell
cargo check --locked --workspace --all-targets
cargo test --locked --workspace
```

4. Запустить `start-windows.bat` или:

```powershell
cargo run --locked --release -p rustmp-server -- --config config.json
```

5. Во втором PowerShell проверить SA-MP Query:

```powershell
cargo run --locked -p rustmp-protocol --example query_client -- 127.0.0.1 7777
```

6. Проверить **отдельно офлайн-пакет** старого RakNet:

```powershell
cargo run --locked -p rustmp-transport --example offline_probe -- 127.0.0.1:7777
```

При успешном ответе увидите двубайтовый ответ и сообщение `Offline pre-handshake response received`. **Это не проверка игрового подключения**. Для проверки реального подключения понадобятся клиент SA-MP и реализованный RakNet reliability layer.

## Структура

```text
Cargo.toml                          рабочее пространство Rust
crates/rustmp-protocol/               SA-MP Query, BitStream и тестовый query-клиент
crates/rustmp-transport/              legacy RakNet offline bootstrap и offline_probe
crates/rustmp-core/                   мир, структура игрока, транспорт и ID pools
crates/rustmp-server/                 UDP event loop, маршрутизация пакетов, ограничения
.github/workflows/rust.yml         cargo check и test для Windows и Linux
config.json                         подмножество конфига open.mp
PORTING_PLAN.md                     план полного порта
CHANGELOG.md                        изменения между версиями
```

## Особенность протокола

У **старого** форка RakNet, используемого SA-MP/open.mp, формат первичного UDP-запроса не совпадает с двухшаговой схемой *современного* RakNet (MTU + `0x05`/`0x07`). Для первой итерации использованы опубликованные исходники старого форка:

- https://github.com/openmultiplayer/RakNet/blob/master/Source/RakPeer.cpp
- https://github.com/Alf21/samp/blob/master/raknet/PacketEnumerations.h
- https://github.com/openmultiplayer/open.mp

Числовые wire ID перенесены из старого enum с учётом `ID_DUMMY_*`. Для окончательной совместимости их требуется сверить с собранным бинарником актуального open.mp и настоящим SA-MP-клиентом. Не смешивайте этот код с современным RakNet/Minecraft Bedrock.

## Ограничения и лицензия

- В разработке применён безопасный Rust без unsafe и без включения исходных C++ файлов.
- Собственные исходники прототипа — MIT; при последующем переносе файлов open.mp нужно соблюдать MPL-2.0 и соответствующие notices, а при переносе сторонних библиотек — их отдельные лицензии.
- `cargo check` и `cargo test` подтверждены GitHub Actions на Windows и Linux для текущего исходного кода. Это **не** означает совместимость с реальным GTA-клиентом.
- До fuzzing и нагрузочных тестов экспонировать прототип в публичный интернет не рекомендуется.

## Сборка и статус

- Исполняемый файл: `rustmp-server.exe` (Windows), `rustmp-server` (Linux).

## Открытая разработка

RUSTMP — общедоступный проект под лицензией MIT. Предложения и исправления можно отправлять через [Issues](https://github.com/Zeihos/RustMP/issues) и [Pull Requests](https://github.com/Zeihos/RustMP/pulls). Не публикуйте секреты, пароли и реальные игровые токены в отчётах об ошибках. Описания безопасности и совместимости должны сопровождаться воспроизводимыми тестами.

Выполнение тестов: `cargo test --locked --workspace`. До проверки wire codec на реальных пакетах клиентов, реализации RPC и игровой сессии RUSTMP **не является заменой рабочему серверу SA-MP/open.mp**.

### Ограничения кодека alpha.5

`rustmp-protocol::legacy_frame` работает только как самостоятельный кодировщик/декодировщик для сообщений с заголовками фрагментации. Он не включён в приём игровых UDP-датаграмм: онлайн-сессии не создаются, игровые пакеты не выполняются. Фрагментированные пакеты поддержаны кодеком; отдельный `SplitAssembler` собирает их только после явной передачи от доверенного вызывающего кода. Режим самостоятельного игрового сервера пока отсутствует. Совместимость должна быть подтверждена тестовыми дампами клиента SA-MP/open.mp; внутренний round-trip сам по себе её не доказывает.

### Безопасность reassembly в alpha.6

Сборщик **должен** создаваться отдельно для каждой подтверждённой сетевой сессии. К нему нельзя передавать непроверенные сообщения напрямую из общего UDP-сокета без аутентификации источника и дедупликации надёжных пакетов. Лимиты: до 64 частей сообщения, до 64 КиБ на одну группу, до 16 групп и 128 КиБ буфера на одну сессию, не более 10 секунд для сборки. Это временные консервативные ограничения, которые могут быть изменены после тестов с настоящими SA-MP/open.mp клиентами.

### Безопасность сессий alpha.7

`VerifiedSessions::admit_verified` является интерфейсом будущего проверенного handshake, а не способом обойти авторизацию. Вызывать его можно **только после** проверки источника, состояния рукопожатия и целостности пакетов. Совпадение `SocketAddr` само по себе не является криптографической аутентификацией. В этой версии входящие игровые датаграммы **не направляются** из публичного сервера в менеджер; реальные клиенты подключаться не могут.

### Техническая сверка служебных ID (alpha.8)

| Сообщение | SA-MP 0.3.7 (Alf21/samp) | openmultiplayer/RakNet RAKNET_LEGACY |
|---|---:|---:|
| Unconnected ping | 3 | 7 |
| Unconnected ping if open | 4 | 8 |
| Reliable connection request | 8 | 11 |
| Offline open request | 16 | 24 |
| Offline open reply | 17 | 25 |
| Offline pong | 37 | 39 |

Источники: [SA-MP header](https://github.com/Alf21/samp/blob/master/raknet/PacketEnumerations.h) и [open.mp RakNet header](https://github.com/openmultiplayer/RakNet/blob/master/Include/raknet/PacketEnumerations.h). Это **два наблюдаемых варианта заголовка**, а не доказательство полной клиентской совместимости. Сервер не отвечает на reliable connection request до реализации безопасной аутентификации, чтобы не выдавать неподтверждённый клиент за подключённого.


### Границы безопасности alpha.9

- `HandshakeCoordinator` является только библиотекой подготовки пакетов и проверки переходов состояний. Он проверяет, что ранее был зарегистрирован офлайн-запрос и наблюдался первый reliable `ID_CONNECTION_REQUEST`.
- Ответ `ID_AUTH_KEY` в оригинальном SA-MP 0.3.7 не используется так же, как в форке open.mp. Для open.mp реальная таблица challenge/response ещё не встроена; **никаких незащищённых тестовых пар в production-коде нет**.
- Сформированные байты являются *полезной нагрузкой надёжного RakNet*, а не готовой UDP-датаграммой. Для реального клиента нужны подтверждение delivery, повторные отправки, проверка cookie и шифрования по профилю, корректная авторизация игры.
- Совпадение IP/порта и ответ на challenge не служат криптографическим доказательством личности. Лишь полная проверка game-auth может создать настоящего игрока.
- Для внешних интеграций из этого модуля **не вызывается** `VerifiedSessions::admit_verified`: пока подключение клиента не подтверждено тестом, игровая сессия остаётся выключенной.


### Ограничения alpha.10

`PreAuthExchange` выдаёт готовые для отправки **RakNet-датаграммы**, но не управляет настоящим UDP-сокетом. Состояние создаётся только после предварительного запроса и проверенного наблюдения `ID_CONNECTION_REQUEST`. Никакая полученная датаграмма не создаёт игрока: результат `transport_confirmed` — лишь прохождение библиотечного протокольного сценария, не авторизация GTA-клиента. Необходимы проверка cookie, ключей/шифрования, тестирование реальных клиентов, интеграция с UDP и разработка game-auth и RPC.

## Проверка локального UDP-handshake (alpha.11)

Это тест **только транспортного протокола**, не игрового подключения. В первом терминале:

```powershell
cargo run --locked --release -p rustmp-server -- --bind 127.0.0.1 --port 7777 --experimental-preauth
```

Во втором терминале:

```powershell
cargo run --locked -p rustmp-protocol --example local_preauth_probe -- 127.0.0.1:7777
```

Пробник отправляет офлайн-запрос и два legacy reliable-пакета, проверяет ACK и завершение транспортного транскрипта. Настоящий SA-MP 0.3.7 клиент, его реальные cookie, ключи, игровые RPC, шифрование и вход в мир остаются непроверенными. Режим нельзя включить на публичном сетевом интерфейсе — он является **локальной диагностикой**, а не игровым сервером. Передача паролей в тестовых запросах производится на loopback; не используйте реальные секреты.
