# План разработки RUSTMP

**Версия прототипа: `0.2.0-alpha.24`**

RUSTMP создаётся как самостоятельная серверная платформа на Rust с целью совместимости с протоколами SA-MP 0.3.7/open.mp. Работа ведётся поэтапно: сначала проверяем сетевой обмен, затем — вход настоящего клиента, синхронизацию и поддержку игровых модов.

> [!NOTE]
> Статусы ниже показывают **реальное состояние кода**, а не обещанные сроки. Результат теста на синтетическом пакете не является доказательством совместимости с настоящим GTA-клиентом.

## Состояние основных этапов

| № | Направление | Состояние | Условие завершения |
| :---: | :--- | :--- | :--- |
| 01 | Rust workspace и кроссплатформенная сборка | **Проверено в CI** | Windows и Linux проходят `cargo check` / `cargo test` |
| 02 | UDP Query и модель мира | **Базовая реализация** | Проверка с реальными query-клиентами и игровым окружением |
| 03 | Legacy RakNet offline / cookie | **Частично** | Корректный обмен с настоящими SA-MP/open.mp клиентами |
| 04 | Надёжный транспорт: ACK, retry, split, order | **Частично** | Действующая надёжная клиентская сессия с потерями/повторами |
| 05 | PCAP-анализ и диагностика handshake | **Тестируется** | Сверка реальных двусторонних клиентских захватов |
| 06 | Полный вход клиента, авторизация, RPC | **Не реализовано** | Клиент входит в игровой мир |
| 07 | Игроки, транспорт и синхронизация | **Не реализовано** | Два настоящих клиента видят изменения друг друга |
| 08 | Pawn/AMX, natives, callbacks | **Не реализовано** | Запускается совместимый `.amx` игровой мод |
| 09 | Плагины, компоненты, NPC, интерфейс | **Не реализовано** | Проверены выбранные API и игровые подсистемы |
| 10 | Безопасность, fuzzing, нагрузка, релиз 1.0 | **Ранний этап** | Доказанная устойчивость и воспроизводимая совместимость |

В `alpha.19` уточнено сопоставление ACK и повторов уже подтверждённых sequence ID: повтор после ACK не создаёт ложную ожидающую запись. Проверка пока выполняется только на синтетических данных.

В `alpha.18` к анализатору PCAP добавлена двусторонняя сверка reliable sequence/ACK с ограничением числа потоков и сохранением только метаданных. Проверка на настоящих клиентах по-прежнему не выполнена.

В **alpha.20** улучшена внутренняя надёжность pre-auth: обработка ACK и стадий handshake стала атомарной, а retry scheduler — циклическим. Добавлены тесты переполнения очередей и справедливости планирования. Совместимость с реальными клиентами всё ещё предстоит проверить.

В **alpha.21** добавлена ограниченная повторная отправка финального ACK после завершения диагностического handshake: точный источник и сообщение сверяются, кэш очищается через 3 секунды или новым offline open. Это локальная транспортная диагностика, не полноценное подключение игрока.

В **alpha.22** закрыты две ошибки управления ресурсами: отклонённые split-пакеты больше не оставляют пустых сборочных групп при переполнении буфера, а ускоренная отправка надёжных ответов не останавливается на неподходящем старейшем сообщении. Добавлены регрессионные тесты перегрузки и восстановления после таймаута.

В **alpha.23** реализован ограниченный планировщик повторных отправок для библиотечных `VerifiedSessions`: до 64 сообщений за цикл и 4 на сессию, детерминированный обход адресов, ACK-отмена и отключение после исчерпания попыток. Приоритет повторов `OutboundReliability` теперь определяется давностью отправки, а не последовательностью ID. Это **не** подключено к игровому UDP listener и не доказывает совместимость настоящего клиента.

В **alpha.24** добавлена атомарная подготовка первого исходящего reliable-пакета через `VerifiedSessions::queue_reliable`, общая сериализация для начального пакета и retry, а также защита ACK-очереди от сброса при ошибке кодирования. Это закрывает внутреннюю несогласованность между начальной отправкой и повторной доставкой; работа пока только библиотечная.

## Ближайший приоритет — настоящая сетевая совместимость

- [x] Базовые профили SA-MP 0.3.7 и open.mp offline RakNet
- [x] Библиотечные кодеки BitStream, ACK, reliable frame и фрагментации
- [x] Локальные тесты pre-auth с ограничениями по IP, памяти и времени
- [x] Офлайн-анализатор `rustmp-trace` для classic PCAP
- [x] Диагностика подтверждений ACK и повторов reliable-кадров в обоих направлениях (синтетические тесты)
- [ ] Снять собственные **двусторонние PCAP** настоящих SA-MP/open.mp клиентов
- [ ] Сверить wire ID, размеры, порядок полей и последовательность cookie/auth
- [ ] Подтвердить обработку потерь, повторов и повреждённых сообщений на реальном клиенте
- [ ] Реализовать и проверить безопасную публичную сессию
- [ ] Включить игровые RPC и авторизованное создание игрока

Для просмотра временной линии захвата:

```bash
cargo run --locked -p rustmp-protocol --bin rustmp-trace -- capture.pcap --port 7777 --handshakes
```

Подробности о формате, ограничениях и безопасности — в [TRACE_ANALYSIS.md](TRACE_ANALYSIS.md).

## После успешного игрового подключения

Приоритеты следующей стадии: синхронизация перемещения и транспорта, управление игроками, Pawn/AMX, совместимость с модами и инфраструктура расширений. Для каждой системы потребуется собственный набор тестов. Публичный релиз будет рассматриваться **только после** подтверждения совместимости с настоящими клиентами и проверки безопасности.

## Принципы проекта

- Не выдавать базовый offline handshake за подтверждённый игровой вход.
- Не отключать ограничения безопасности ради прохождения протокольного теста.
- Не копировать сторонние C++-исходники без соблюдения лицензий и notices.
- Сохранять воспроизводимые проверки на Windows и Linux.
- Документировать отличия от SA-MP/open.mp вместо выдумывания «совместимости».
