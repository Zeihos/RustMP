# Участие в разработке RUSTMP

Спасибо за интерес к проекту. RUSTMP — **экспериментальная** Rust-реализация отдельных протокольных компонентов SA-MP/open.mp, а не готовый игровой сервер.

## Перед началом

1. Проверьте [README.md](README.md), [PORTING_PLAN.md](PORTING_PLAN.md) и открытые Issues. Для крупных изменений сначала обсудите цель и границы задачи.
2. Воспроизводите ошибки на последнем `main`, указывая OS, версию Rust и точные команды.
3. Делайте небольшие тематические изменения. Не смешивайте форматирование всего репозитория, сетевой протокол и новые функции в одном Pull Request.

## Локальная проверка

```bash
cargo check --locked --workspace --all-targets
cargo test --locked --workspace
```

Для изменённых Rust-файлов используйте `cargo fmt --all`. Старые исходники пока не приведены к единому стилю, поэтому массовое форматирование **не должно** быть частью функционального PR без отдельного согласования. Используйте `cargo clippy --workspace --all-targets` для поиска потенциальных проблем; замечания в старых модулях обсуждаются отдельно.

GitHub Actions проверяет workspace на Windows и Linux. При изменении протокола нужны тесты кодирования/декодирования, повреждённых входных данных, границ буферов и повторных сообщений. Для UDP-интеграции предпочтительны тесты на `127.0.0.1`, которые запускают реальный бинарник и не требуют игрового клиента.

## Pull Request

- Укажите **что изменено**, **зачем**, **как проверено** и что **пока не работает**.
- Не заявляйте поддержку настоящих SA-MP/open.mp клиентов без подтверждения реальным клиентом или проверенным трассированием.
- Поддерживайте `README.md`, [CHANGELOG.md](CHANGELOG.md) и [PORTING_PLAN.md](PORTING_PLAN.md) в актуальном состоянии, если меняется функциональность.
- Для исправления ошибки добавьте регрессионный тест, если возможно.
- Не меняйте лицензию стороннего кода и не копируйте файлы из других проектов без выполнения их лицензионных условий.

## Безопасность и приватность

- Не добавляйте настоящие пароли, токены и неочищенные `.pcap` / `.pcapng` в коммиты, Issues или PR.
- Используйте **синтетические** фикстуры и локальные тестовые окружения.
- Экспериментальный handshake доступен только на IPv4 loopback и не предназначен для публичного сервера.
- Сообщения об уязвимостях — по [SECURITY.md](SECURITY.md), **не** в публичном Issue.
