# RUSTMP: анализ сетевых захватов SA-MP/open.mp

Версия 0.2.0-alpha.19. Это офлайн-анализатор протокольных метаданных, а НЕ самостоятельный клиент GTA и НЕ доказательство полной совместимости RakNet.

## Использование

Для анализа UDP-пакетов из Wireshark, сохранённых в классический формат PCAP (.pcap):

    cargo run --locked -p rustmp-protocol --bin rustmp-trace -- capture.pcap --port 7777

IP-адреса скрыты по умолчанию. Чтобы явно показать IP и порты:

    cargo run --locked -p rustmp-protocol --bin rustmp-trace -- capture.pcap --port 7777 --show-endpoints

Команда показывает номер записи, время, порты, длину UDP, предполагаемый тип SA-MP Query или RakNet offline, число диапазонов ACK, количество frames, sequence/reliability/order/split первого кадра. Имена, пароли, токены, произвольный payload НЕ печатаются.

Файлы PCAPNG пока не поддерживаются напрямую. В Wireshark выберите File > Save As и классический формат pcap; альтернативно в терминале:

    tshark -r capture.pcapng -F pcap -w capture.pcap

## Поддерживаемые форматы

- Classic PCAP v2.4: little/big endian, microsecond/nanosecond timestamps
- Ethernet (LINKTYPE 1) с максимум двумя VLAN-тегами; RAW IPv4 (101)
- BSD loopback (0), Linux cooked v1 (113) и v2 (276), только IPv4/UDP
- SA-MP Query, ограниченные offline-пакеты SA-MP/open.mp и legacy RakNet frames, распознаваемые текущим кодеком

НЕ поддерживаются: pcapng, IPv6, сборка фрагментов IP, шифрование, декодирование игровых RPC, все вариации RakNet, проверка IP/UDP checksum и подтверждение аутентичности пакета. Классификация пакетов эвристическая: некоторые неизвестные сообщения могут совпадать по первым байтам.

## Ограничения и приватность

- Максимум 32 МиБ на файл; 256 КиБ на запись; 65 536 записей и 32 768 UDP-событий
- IP-фрагменты пропускаются (не пытаемся декодировать неполные UDP-пакеты)
- Публичная структура отчёта содержит IP-адреса и порты, но НЕ содержит raw payload. Консоль скрывает IP по умолчанию
- САМ файл .pcap может содержать секреты и личные данные, даже если эта программа их не выводит. Не размещайте неочищенные дампы в публичном GitHub
- Анализатор не подключается к живому UDP-серверу и не разрешает подключение настоящих игроков

## Временная линия offline handshake (alpha.17)

    cargo run --locked -p rustmp-protocol --bin rustmp-trace -- capture.pcap --port 7777 --handshakes

Требуется явный --port: без него нельзя надёжно установить направление клиент → сервер. Вывод группируется по точной паре endpoint (IP и UDP-порт) и по профилю протокола. Для каждого потока указаны запросы, повторные запросы, cookie challenges, offline replies и аномалии порядка. По умолчанию IP скрываются; чтобы показать их, отдельно укажите --show-endpoints.

Статус OfflineReplyObserved означает **только то, что в захвате найден offline reply**. Это не полноценная RakNet-сессия и не успешное подключение игрока. AwaitingReply означает отсутствие ответа **в захвате**, а не доказанную потерю пакета. В захвате могут отсутствовать некоторые направления, может быть включена фильтрация, таймстемпы могут отличаться. Нельзя по этим числам доказать причину потери без дополнительного сетевого теста.

Предел анализа — 2048 различных пар endpoint+profile. Отчёт не содержит паролей, ключей и raw payload; исходный файл PCAP по-прежнему может содержать чувствительные данные.

## Анализ ACK и повторных reliable-кадров (alpha.19)

    cargo run --locked -p rustmp-protocol --bin rustmp-trace -- capture.pcap --port 7777 --reliable

Опция `--reliable` требует указания UDP-порта сервера. Программа сопоставляет клиентские и серверные номера **надёжных** кадров с ACK-подтверждениями противоположной стороны. Для каждого потока показываются число кадров каждого направления, количество подтверждённых, повторные последовательности, ещё не подтверждённые **в захвате** и ACK, для которых в захвате не нашлось исходного кадра. Опции `--reliable` и `--handshakes` можно использовать одновременно.

Для диагностики используются только номера кадров, тип надёжности и диапазоны ACK. Полезные нагрузки, пароли, токены и содержание игрового трафика не сохраняются в отчёт и не печатаются. IP-адреса скрыты, если явно не указан `--show-endpoints`.

Важные ограничения: без настоящих сетевых дампов неизвестно, полностью ли соответствует кодек реальным клиентам. Неподтверждённое сообщение может находиться вне интервала захвата, ACK может быть потерян при записи, а повторы чисел могут возникнуть при новой сессии. `rustmp-trace` не устанавливает, было ли сообщение реально доставлено. Лимиты анализа — 1024 пар IPv4-адресов/портов и 512 ожидающих подтверждения последовательностей **на направление** в одной паре. При достижении лимита новые номера не учитываются и их количество сообщается отдельно.

### Повтор после ACK и повторные подтверждения

В alpha.19 добавлены две отдельные категории:

- `repeated_acks` — повтор ACK для sequence ID, уже подтверждённого в ограниченной истории того же направления, вместо ошибочного `unmatched_acks`.
- `client_reused_after_ack` / `server_reused_after_ack` (итоговая сумма `reused_after_ack`) — уже подтверждённый номер снова встретился в кадре с надёжной доставкой. Он **не создаёт** повторно ожидающую подтверждения запись.

В истории хранится не больше 512 номеров ACK на направление и поток. После вытеснения старого номера повтор может уже не распознаться. Такой номер может появиться при повторной передаче, смене соединения, переполнении sequence или другом переиспользовании ID. **Без настоящего клиента и идентификатора сессии это только подсказка для анализа PCAP, а не доказательство сетевого сбоя.**
